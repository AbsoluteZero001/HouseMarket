# 面试技术选型建议

这个项目的亮点是预约流程闭环：发布 → 预约 → 审批 → 通知。经过企业级演进后，已经具备状态机原子流转、流程轨迹可追溯、事务 Outbox 异步通知、乐观锁、幂等键、缓存与限流等可讲的技术点。

## 已经落地的企业级能力

### 乐观锁 + 唯一约束

预约审批的并发核心是“同一房源同一时间不能被重复预约、状态不能被并发覆盖”。当前实现：

- `appointment` 表带 `version` 字段，配合 MyBatis-Plus `@Version` 与 `OptimisticLockerInnerInterceptor`。
- `(house_id, time, status)` 冲突检查作为业务校验，`request_id` 唯一索引作为幂等兜底。
- `appointment_flow` 流水表保存每一次状态变化，天然可审计。

### 幂等键

前端提交预约时生成 `requestId`，后端在插入前按 `request_id` 查询，插入时依靠唯一索引拦截并发重复提交，重复请求直接返回已有预约。这个模式可以继续延伸到支付、收藏、点赞等写操作。

### 事务 Outbox 异步通知

预约状态变更和 `notification_outbox` 写入处于同一事务，保证“状态变了但通知没发”不会发生。`NotificationOutboxProcessor` 定时轮询：

- 先通过条件更新将 `pending` 抢为 `processing`，多实例下保证每条消息只被一个消费者处理。
- 投递 WebSocket 成功后标记 `sent`。
- 失败自动重试，超过阈值标记 `failed`。

这是典型的分布式事务最终一致性方案，面试时可以讲清楚 Outbox 与 MQ 的关系：当前用 DB + 定时任务替代 MQ，演进到 RocketMQ/Kafka 时只需要把 Outbox 轮询替换为发消息。

### 缓存与限流（Redis-ready）

- 房源列表、房源详情、首页统计通过 Spring Cache 缓存，默认 `simple` 本地缓存。
- 登录、注册接口做固定窗口限流，默认 `InMemoryRateLimiter` 单机实现。
- `redis` profile 下切换到 Redis 缓存与 `RedisRateLimiter`，多实例共享计数。

面试时重点讲：缓存穿透/击穿/雪崩、Key 设计、缓存与 DB 一致性（更新 DB 后删缓存 / 双删 / 延迟双删），以及为什么默认内存缓存、生产切 Redis。

### 通知中心与浏览统计

- 租客端、房东端新增“通知中心”，通过 `GET /api/notifications` 查询已送达的历史通知。
- 房源详情访问自动累计 `views`，通过缓存驱逐保证详情数据一致性。
- GitHub Actions CI 覆盖后端测试（含 MySQL 服务）和前端构建。

### 房东入驻审核

- 新增 `landlord_application` 申请表，房东注册后先进入 `pending`。
- 管理员在“房东审核”页通过或拒绝，审核结果写入事务 Outbox。
- 审核通过前，`/api/houses` 的发布和修改接口会拒绝房东操作。
- 审核结果通过通知中心推送给房东，形成“注册 → 审核 → 发布 → 预约 → 审批 → 通知”的完整权限与业务闭环。

## Redis / 分布式锁怎么取舍

分场景看，不要为了“有”而加。

### 不建议盲目加：分布式锁

分布式锁只解决“多实例并发操作同一资源”的问题。当前单实例部署时，乐观锁 + 唯一约束 + 事务 Outbox 已经足够，引入 Redisson 会增加部署成本。

如果面试想展示分布式锁，正确的说法是：

- 只有房源预约、抢房这类强并发场景、且确认会多实例部署时才使用。
- 锁粒度按 `houseId:timeSlot` 设计，尽量缩小临界区。
- Redisson 看门狗解决锁过期问题，但真正的一致性兜底仍是数据库唯一约束或条件更新。

### 悲观锁什么时候用

`SELECT ... FOR UPDATE` 适合“先查再算再写”、无法用条件更新表达的业务。预约场景里乐观锁 + 条件更新更简单，悲观锁会长时间占数据库连接，通常只在低并发后台任务中使用。

## 继续演进的方向

1. **消息队列替换 Outbox 轮询**
   把 `NotificationOutboxProcessor` 的定时轮询换成 RocketMQ/Kafka，投递语义从 DB 轮询变为 MQ 消费，面试可以讲清“为什么当前不需要 MQ”。

2. **Redis 分布式锁**
   多实例部署后，对同一房源同一时间槽的预约用 Redisson 加锁，缩小临界区，数据库唯一索引继续兜底。

3. **登录会话与安全**
   JWT 无状态会话升级为 Redis token 管理，支持主动下线、token 黑名单；限流可升级为 Redis 滑动窗口或令牌桶。

4. **搜索与地理位置**
   房源搜索升级到 Elasticsearch，支持多条件组合、排序、附近房源；面试重点是索引设计和查询 DSL。

5. **文件存储**
   本地 `uploads/` 适合教学和复现，生产演进可用 MinIO/OSS，并说明为什么本地存储不适合多实例部署。

6. **可观测性**
   接入 Spring Boot Actuator、Micrometer + Prometheus + Grafana，补全接口耗时、缓存命中率、Outbox 积压量等监控指标。

## 一句话结论

项目现在已具备事务 + 状态机 + 流程轨迹 + 版本号乐观锁 + 幂等键 + 事务 Outbox + Redis-ready 缓存/限流，可以完整讲清“懂业务、懂并发、懂取舍”。分布式锁和 MQ 只在确认多实例、高并发后再引入，面试时主动说明这个判断比“什么都加”更加分。
